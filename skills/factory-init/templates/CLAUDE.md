# コンパクションへの備え（Claude Code）

コンパクションのあとに残るのは、このファイルと AGENTS.md、最近書き換えたファイルの一部、呼んだスキルの本文の先頭まで。会話は要約に置き換わり、道具の出力と途中の考えは消える。

- **決まったことはファイルに書く。** ユーザーが会話で決めたことと却下したこと（理由も）、要確認は、その都度 `構成案*.md` か `社内メモ_*.md` に書き足す。ページに出す事実（数字・提供の状況・顧客の環境・固有名詞）は、ページより先に構成案の「出典の表」に足す。修正の指示は決まりの台帳（`ledger.py add`。AGENTS.md の「修正の指示」）に書く。
- **重い読み物はサブエージェントに任せる。** 会議の文字起こし、広い検索、スライドの画像の確認は、サブエージェントに渡して、要点と出典だけを受け取る。読ませた材料は、作業中のフォルダの `references.md` に `refs.py add` で足させ（同じ子が並んでも ID はぶつからない）、事実は出典の ID（`S3`）と場所を付けて返させる。
- **コンパクションのあとは読み直す。** 作業中のフォルダの `構成案*.md`・`社内メモ_*.md` と、顧客の `memory.md`・`profile.md`、その資料の指摘（`ledger.py list --deck <資料のフォルダ>`）。`references.md` は出典を確かめるときに開く。作っている途中なら、deck-practices の SKILL.md の「What to read when」の表のファイル（と `rules/` の同じパス）のうち、次の手順に要る節だけを開く（丸ごと読み直すと文脈がすぐ元に戻る。deck-practices の deck-flow-015）。

# Compact Instructions

要約では次を残す。

- 作業中のフォルダ、納品物の名前と Drive の URL、構成案の版
- ユーザーの指示、決めたこと、却下した案とその理由（ユーザーの発言はできるだけ原文のまま）
- 数字・固有名詞と、その出典
- 社内だけの情報と、顧客に出せる情報の区別
- 確認の結果（lint の要修正と残した要確認、画像で見つけた不具合）と、まだ確認していないこと
- 未解決の問題と次の一手
