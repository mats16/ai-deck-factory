# 日本語のスライドを作って仕上げる

スライドは Google Slides を Slides API で直接組む（2026-10-07 に pptx から切り替えた）。pptx の方式に戻すときは ワークスペースの `Archive/pptx_pipeline_20261007/README.md`。ドキュメント（Google Docs）は `../doc-build/`。`scripts/` はドキュメントと共有する（`gapi.py`・`lint.py`・`sheet.py`・`drive_put.py` と、ドキュメントの `docs.py`・`doc_layout.py`）。

| 作るもの | 書き始める前に読む |
|---|---|
| スライド | [slides.md](slides.md)（コマンド、pages.py の書き方、テンプレートとテーマ、図形と文字の組み方、Slides API の落とし穴）と `../deck-practices/visual.md`（このフォルダの見た目の決まり） |
| ドキュメント | `../doc-build/SKILL.md`（Google Docs） |
| 社内資料の流用 | `../deck-practices/reuse.md`（`scripts/gslides.py` で Google Slides のページの一覧・画像を取り、`keep`・`jp` で差し替え用のページを作る） |

```sh
K=<deck-build のフォルダ>/scripts   # deck-build の SKILL.md のあるフォルダ。ほかのスキルからは、そのスキルのフォルダの ../deck-build/scripts
cd <フォルダ>/build
# スライド
python3 $K/slides.py new <Drive のフォルダの URL> <YYYYMMDD_の名前>   # 初めて組むとき（下の「Drive に置く」）。--theme company で会社の色
python3 $K/slides.py build <URL>                                    # 直したら組み直す（URL は変わらない。画面で直されていたら止まる。slides.md の 1）
python3 $K/gslides.py check <URL>                                   # LT など話す資料は末尾に --talk
```

## gslides.py check がすること

1. `presentations.get` の JSON を `/tmp/slides_<ID の頭 8 字>/deck.json` に書く
2. ページごとの文字とノートを `deck.md` に書き出す（レビューに渡すテキスト）
3. `lint.py`（下）を JSON にかける
4. 全ページの画像（Google が描いたサムネイル、1600 × 900）を `p-NN.png` に取る（6 本並列。`--pages 3,5` で一部だけ取り直す）
5. `box_pad.py` が、取った画像で、塗りの箱の中の上寄せの 2 行以上の文字と箱の下端の間を測り、1 字分より狭いものを「要確認（画像で測った）」に出す（visual.md の 4。行の高さは JSON では見積もれないので画像で測る。2026-10-09）。1 つだけで置く淡色のパネルの上寄せの文字で、下の空きが上より 0.25 in 以上大きいものも出す（中央に置くか縮める。2026-10-10）

lint の要修正があれば、画像まで取ったうえで exit 1 を返す。

## lint.py がすること

書いたルールは守られにくいので、機械で見られるものはここで数える（標準ライブラリだけ。単体でも `python3 lint.py <deck.json>` で動く）。ルールの中身と出典は `deck-practices`。テーマの色は、デッキのマスターの配色で実際の色に直して見る。

- **見出しの一覧:** 各ページでいちばん大きい文字を順に出す。1 行に収まらない見込みなら「2 行の見込み」と付ける。これを通して読み、話が通るかを見る（`deck-practices` の content.md）。
- **本文の字数:** ページごとに、見出し・リード・出典・フッターを除いた字数を出す。`--talk`（LT など話す資料）のときは、125 字を超えるページを要確認に出す（content.md の 2）。
- **要修正（exit 1）:** 絵文字、長いダッシュ（—）、置き換え忘れ（TODO、〇〇、lorem など）、社内資料の差し替えの仮ページの札（「差し替え：」）、スライドの 11pt 未満の文字（著作権フッターと同じ行の秘密区分だけは 9pt 未満。名前に「差し替え用」が入ったデッキは、元のページの大きさのままなので見ない）、Noto Sans JP でない書体（英数字だけの Cascadia Mono は通す）、Cascadia Mono（等幅）の和文。
- **要確認:** 空疎な言い回し（「〜を実現する」など）、不安をあおる言い方、英語の大文字のラベル（等幅のコードの行は数えない）、和欧間のスペースの抜け、約物の前後のスペース、「要確認」「TBD」の残り、社外秘の表示（Internal Only・Confidential など。フッターのものは 1 件にまとめる）、スライドの本文の です・ます、ノートの だ・である、ノートのないページ、出典の行がないページの数字、リンクのない出典の行、8 行を超える本文（どちらも等幅のコードの箱は数えない。`source:` を出典の行と見ない）、見出しかリードが 2 行の見込み、両側の箱の上下の中央にない横の矢印、線で組んだ格子（上端と長さの同じ縦線が 3 本以上。細い四角も線に数える。矢印と、角丸の囲みのグループの中の線は数えない。表にする）、本文の下の空き（結論バンドか 6.60 in まで 1.0 in 以上）、中身より大きい箱（塗りの箱の、文字より下が 0.6 in 以上。角丸を組む部品や枠線のような文字のない図形は中身に数えない）、本文の中ほどの穴（要素と要素の間・結論バンドの上が 0.65 in 以上、本文の上が 1.0 in 以上。表の下は数えない）、数字だけの大きな段落（28pt 以上で単位がない）、隣り合う列の白いカードの上端・下端のずれ（0.03〜1.0 in）、Google 標準の丸みの点線の角丸（中のカードと曲率が合わない。`d.box(…, dash=True)` にする）、本文の 3 分の 1 を超える結論バンド、1 枚目が表紙（濃紺の地）でないデッキ、12 枚を超えるのに章の扉（濃紺の地）がないデッキと、扉のあとが 1 枚だけ（か 1 枚もない）の章。
- **組むときの警告**（slides.py が出す。手で改行した行が枠に収まらない、見出しを縮めた、リードが 2 行、表のセルが折り返す）も、要確認と同じように 1 件ずつ見る。
- **文字サイズの分布**と、**コントラストが基準に届かない色の組**（18pt 未満は 4.5:1、それ以上か 14pt 以上の太字は 3:1。文字の下にある塗りを地として計算する。画像の上の文字は見ない。章番号のような飾りの文字は出ても構わない）。
- ドキュメントの規則（Google Docs）は `../doc-build/SKILL.md` の 3。文章の規則（絵文字から「要確認」の残りまで）は、スライドと共有する。
- 和文の言語（`ja-JP`）は Slides API で付けられないので、数えない（slides.md の 5）。
- **記録:** `gslides.py check`・`docs.py check` は、要確認を `log/lint_runs.jsonl` に 1 回 1 行で残す（資料の文は残さず、指摘のハッシュだけ）。`python3 lint.py --stats` が、規則ごとに、出た件数と、その資料の最後の確認まで残った件数を出す（dreaming の 5 で使う）。

## 結果の見方

- **画像:** 組んだら、変えたページの画像を自分で開いて見て、直す（`--pages 3,5`。初めて組んだときは全ページ）。見るところは、はみ出し（文字は枠から出ても切れない）、重なり、出典やフッターとの衝突、行頭の句読点、1〜2 字だけの最終行、単語や文節の途中での折り返し。仕上がりは Google が描いたこの画像で判断する。
- **テキスト:** 抜けや順番の誤りがないか、`deck.md` を読む。
- **lint:** 要修正は 0 にする。要確認は 1 件ずつ見て、直すか、残す理由を言えるようにする（例: 顧客の発言の引用に です・ます が残るのはよい）。
- **返す前:** ユーザーに返す前に `/deck-review`（`../deck-review/SKILL.md`）で全体をレビューする。別のサブエージェントの目と、全ページの一覧で見る。
- 確認が済んだら `/tmp/slides_<ID>/` は消してよい。資料のフォルダには残さない。

## 納品物

- **スライドは Google Slides、ドキュメントは Google Docs（`../doc-build/`）を納品する。PDF は作らない。** HTML の資料を PDF にして渡したもの（顧客向けの資料など）は残してある。2026-10-07 より前のスライドは pptx（直し方は slides.md の 7）、2026-10-09 より前のドキュメントは docx（直すときは Google Docs に変換する。`../doc-build/SKILL.md` の 8）。
- **書体:** スライドとドキュメント（Google Docs）は Google Fonts の Noto Sans JP（スライドは、会社のテンプレートから作ったテーマならその書体。lint はテンプレートのマスターの書体と比べる。`../deck-template/SKILL.md`。ドキュメントは Noto Sans JP のまま）。コードの箱とコマンドの英数字だけは等幅の Cascadia Mono（`slides.py` の `MONO`。`../deck-practices/visual.md` の 2。2026-10-09）。
- **文字の大きさ:** スライドの文字は 11pt 以上（表紙・扉・出典・ページ番号も。著作権フッターと同じ行の秘密区分だけ 9pt。2026-10-08）。書体と大きさは lint が止める。Google Slides は言語を付けられないので、行頭の句読点は画像で見る（slides.md の 5）。
- **名前と改訂:** 資料名は `<相手>_<内容>_<日付>`。Drive 上の名前は下の「Drive に置く」。改訂は同じファイル（スライドは同じ URL）に上書きし、前の版は理由があるときだけ `_v2` で残す。`.bak` は作らない。
- `slides.py` で組んだデッキは画面で直さず、pages.py を直して組み直す（画面での直しは消える。画面で直されていたら `slides.py build` が止まる。slides.md の 1）。ドキュメントは `../doc-build/SKILL.md` の 6。
- `~$` で始まるファイルは PowerPoint や Word のロックファイル。開いている最中に作られるので触らない。

## Drive に置く

スライドとドキュメントで同じ。スライドは Google Slides、ドキュメントは Google Docs として Drive に直接作り（ドキュメントは `docs.py new`。2026-10-09 から）。人には URL で渡す（上の「納品物」。2026-10-07 にユーザーが決めた）。

- **置き場所:** 共有ドライブの `10_Customers`（URL は ワークスペースの `factory.toml` の `drive.customers`）→ 社名の頭文字のフォルダ（`00_ABC`、`01_DEF` など）→ 顧客（英語の社名）→ 事業部などのフォルダ。先に `references_index.md` の「Google Drive の置き場所」を見る。載っていなければ中を見て決め、そこに足す。
- **顧客に紐づかない資料（`Internal/`）:** スライドは My Drive の「AI Deck Factory」の中の「Slides」（URL は `factory.toml` の `drive.internal`）、ドキュメント（Google Docs）は同じ中の「Docs」（`drive.docs`。2026-10-10、ユーザー「顧客関係ない資料は AI Deck Factory 配下に Docs というフォルダを作り、そこに配置する」）。どちらも共有ドライブではない → テーマごとのサブフォルダ。合うものがなければテーマの名前で作る（2026-10-07 にユーザーが指定）。個人の資料（テンプレート・社内向けの成果物）は AI Deck Factory の下にまとめ、My Drive の直下に置かない（2026-10-08 にユーザーが決めた。画像を貼るときの仮のファイルだけは例外で、slides.md の 6）。
- **名前:** Drive 上は `YYYYMMDD_` で始める（いつのものか分かるように）。日付は会議や提出の日、決まっていなければ初めて作った日。後ろは資料名（上の「納品物」の資料名から、末尾の日付と拡張子を外したもの）。例: `20261007_Acme様_ご説明資料_SIEMの事例と構成`。
- **スライドを作る:** `slides.py new <フォルダ> <名前>` が、テンプレートをそのフォルダに複製して組む。出た URL を構成案（か社内メモ）に書く。代表の 3 枚や下書きの段階から、決まりの置き場所（顧客のフォルダ）に作ってよい。仕上げる前から社内の人に見えても問題ない（2026-10-08 にユーザーが決めた）。
- **更新:** スライドは `slides.py build <URL>` で同じプレゼンを組み直す（URL が変わらない）。html・csv は `drive_put.py` で同じファイルに上書きする。名前の日付は変えない。別にコピーを残すのは、指示があったときだけ。
- **名前を変えるとき:** Drive API の `files.update`（PATCH で `{"name": …}`、`supportsAllDrives=true`）で変える。ID・URL は変わらない（2026-10-07 にユーザーが決めた）。`drive_put.py` で上げるファイルは、先に Drive 上の名前を変えてから、新しい名前で `drive_put.py` を回す（名前で上書き先を探すので、先に変えないと別のファイルがもう 1 つできる）。
- **html・csv などのファイルの上げ方:** `python3 $K/drive_put.py <ファイル> <フォルダの URL か ID> <Drive 上の名前>`（同じ名前があれば上書き、なければ作る）。
- 共有の設定は変えない。作った資料は `references_index.md` の「Google Drive の置き場所」に、ローカルのフォルダと組にして足し、URL を報告に付ける。

## Google Slides・Google Docs 以外

- **HTML の資料** は頼まれたときだけ作る。1 ファイルで完結させ、画像は同じフォルダの `images/` に置く。手元で見るときは `.claude/launch.json` に `python3 -m http.server` の設定を足す。
