# Placing files on Drive

Where and under what name slides and documents go on Drive, and how to upload other files. Read when you create a deck or a document (`slides.py new`, `docs.py new`), rename one, or upload html, csv, or a research note.

[deck-drive-001] Same for slides and documents. Create slides as Google Slides and documents as Google Docs directly on Drive (documents with `docs.py new`. Since 2026-10-09). Give them to people as URLs ("Deliverables" in `../slides-build/SKILL.md`; for documents, `../docs-build/lint.md`).

- **Location:** The shared drive's `10_Customers` (the URL is `drive.customers` in the workspace's `factory.toml`) → the folder for the company name's initial (`00_ABC`, `01_DEF`, and so on) → the customer (company name in English) → a folder for the business unit or similar. Check 「Google Drive の置き場所」 in `references_index.md` first. If it is not listed, look inside, decide, and add it there.
- [deck-drive-002] **Materials not tied to a customer (`Internal/`):** Slides go in 「Slides」 inside 「AI Deck Factory」 in My Drive (the URL is `drive.internal` in `factory.toml`), and documents (Google Docs) in 「Docs」 in the same folder (`drive.docs`). Neither is a shared drive → a subfolder per topic. If none fits, create one named after the topic. Keep personal materials (templates, internal deliverables) under AI Deck Factory and not directly in the root of My Drive (the only exception is the temporary files used when pasting images, `../slides-build/images.md`).
- **Name:** On Drive, start with `YYYYMMDD_` (so it is clear when it is from). The date is the meeting or submission date, or the date you first created it if not decided. After that comes the material name (the material name from "Deliverables" in `../slides-build/SKILL.md`, without the trailing date and extension). Example: `20261007_Acme様_ご説明資料_SIEMの事例と構成`.
- [deck-drive-003] **Creating slides:** `slides.py new <folder> <name>` copies the template into that folder and builds. Write the printed URL in the outline (or the internal memo) and tell the user on the spot in one line (「作業中の資料: <URL>。組み直すたびに同じ URL が新しくなる」). This lets them watch it in the UI before it is finished. Do not wait for a reply; keep going. The same goes for `docs.py new` for documents. You may create it in the rule-defined location (the customer's folder) from the three representative pages or draft stage. It is fine for internal people to see it before it is finished.
- **Updating:** For slides, rebuild the same presentation with `slides.py build <URL>` (the URL does not change). Overwrite html and csv in the same file with `drive_put.py`. Do not change the date in the name. Keep a separate copy only when told to.
- [deck-drive-004] **Renaming:** Rename with the Drive API `files.update` (PATCH with `{"name": …}`, `supportsAllDrives=true`). The ID and URL do not change. For files uploaded with `drive_put.py`, rename on Drive first, then run `drive_put.py` with the new name (it finds the file to overwrite by name, so if you do not rename first, a second file is created).
- **Uploading files such as html and csv:** `python3 <deck-practices folder>/scripts/drive_put.py <file> <folder URL or ID> <name on Drive>` (overwrites if the same name exists, otherwise creates). `drive_put.py research Research/<topic>_<YYYYMMDD>.md` converts a research note to Google Docs and uploads it to `Research` under `drive.factory` (created if missing), named `<YYYYMMDD>_<topic>` (「調べもの」 in the workspace's AGENTS.md).
- Do not change sharing settings. Add the materials you made to 「Google Drive の置き場所」 in `references_index.md`, paired with the local folder, and include the URL in the report.

## Formats other than Google Slides and Docs

- **HTML materials:** Make them only when asked. Keep each in one self-contained file, with images in `images/` in the same folder. To view locally, add a `python3 -m http.server` entry to `.claude/launch.json`.
