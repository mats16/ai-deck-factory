# ドキュメントの見た目の決まり（Google Docs）

提案書・調査レポート・説明資料・PoC の計画書を、Google Docs で組むときの見た目の決まり（2026-10-09 に作った）。スライドの決まり（[visual.md](visual.md)）は当てはめない（下の 6）。中身の書き方は [content.md](content.md)（スライドと同じ）、組み方は `../doc-build/SKILL.md`。値は `docs.py` の版面の定数と `STYLES` にあり、組むたびに入るので、doc.md には書式を書かない。

確かめ方（[rules.md](rules.md) の「決まりの確かめ方」）: 「lint が」は `lint.py` の `lint_gdoc`、「画像で測る」は `doc_layout.py`（どちらも `docs.py check` が回す。check は doc.md と組んだ文書、テンプレートとの照合もする。`../doc-build/SKILL.md` の 2）、札のないものはレビュー（`../deck-review/prompt_doc.md` の観点）。括弧の中の略称は、ワークスペースの `Research/deck_research/log/` の報告で、「文書」は `20261009_jp_doc_content_visual.md`、「Docs」は `20261009_en_gdocs_generation.md`。

## 1. 版面・書体・行間

- **A4 縦、上下 25 mm・左右 30 mm。1 行は全角 40 字まで**（本文 10.5pt で本文の幅 150 mm。Word の和文の既定と同じ）。lint が用紙（A4 でなければ要修正）と 1 行の字数を見る（文書 1-12。jlreq・デジタル庁）。
- **書体は Noto Sans JP**（Regular・Bold）。コードの英数字だけ Cascadia Mono。lint が書体を見る。印刷して読む長い文書で明朝にするかは、資料ごとに聞く（文書 1-16）。
- **大きさ:** 本文 10.5pt、H1 15pt・H2 12.5pt・H3 11pt（太字・濃紺）、題 20pt、副題 11pt、表の中・図表の題・出典・フッター 9pt、コード 9.5pt。9pt 未満は lint が止める。
- **行間:** 行送りは「字の 1.88 倍 × 行間の %」になる（Noto Sans JP。2026-10-09 に PDF で測った。Slides の % とは違う）。本文 100%（行のアキ 0.88 字）、表の中・図表の題・出典 80%（二分）、見出し 75%、コード 85%（文書 1-13。小林敏「行間の選択」）。
- **段落は段落後の空き（6pt）で区切り、字下げしない。** 空の段落で間をあけない（lint が「空の段落の連続」）。左揃えにする。両端揃えは、和欧間のスペースが広がらないかを測るまで使わない（文書 1-14・1-17）。
- **地は白。色は役割で固定する:** 見出しと表の見出しの行は濃紺 `1B3139`、本文 `303F47`、補助（図表の題・出典・引用・フッター）`5A6F77`、罫線 `DCE0E2`、コードの地 `EEEDE9`、リンクは Google Docs の既定の青。赤のアクセントは使わない。白黒で印刷しても読めるようにする（文書 1-10・2）。
- **フッター**に著作権表示と秘密区分（`NAME` の末尾。スライドと同じ）。ページ番号と目次は API で入れられない（`../doc-build/SKILL.md` の 7）。提出する提案書・計画書でページ番号が要るときは、画面で入れる。

## 2. 構成と見出し

- **表紙のページは作らない。** 1 ページ目の頭に題と副題（日付・宛先）を置く（`d.title`）。提出する提案書で表紙が要るかは、資料ごとに聞く。
- **題には主題と文書の性格（提案・報告・計画・回答）を入れ、1 行に収める。** 「〜について」で終えない（lint が。文書 1-3。公用文作成の考え方）。
- **最初の章を要旨にし、結論と、読み手に求めること（判断・次の一歩）を最初の段落で言う。** 細目は後ろか付録に回す（lint が「冒頭に要旨がない」。要旨だけで判断できるかはレビュー。文書 1-1）。結論を末尾の「まとめ」で繰り返さない（lint が。Docs 1-15）。
- **書く前に、構成案にページ数の上限を書く。** `docs.py check` のページ数と比べ、超えたら必要性の低いものから削る（文書 1-2）。
- **見出しは 3 段（H1 章・H2 節・H3 項）まで。** 段を飛ばさない、子を 1 つだけにしない（「2.1」だけで「2.2」がない）、同じ見出しを 2 回使わない、句点を付けない、太字の段落を見出しの代わりにしない（左のアウトラインに出ない）。lint がすべて見る（文書 1-4）。
- **章（H1）の見出しは項目名でよい**（「要旨」「背景」、RFP の評価項目）。主張は節（H2・H3）の見出しか、段落の 1 文目で言う。スライドの「見出しは主張の文」は、ドキュメントの章には当てはめない（文書 2）。
- 番号は見出しの文字で付ける（「1. 要旨」「2.1 いまの構成」）。

## 3. 段落と文

- **1 段落に 1 つの話題。1 文目でその段落の要点を言う。** 1 文目だけを順に読んで要約になるかを確かめる（スライドの「見出しだけを順に読む」に当たる）。lint が見出しと 1 文目の一覧を出し、レビューで読む。1 段落は 3〜8 文で、9 文以上は lint が出す（文書 1-5。木下是雄）。
- **一文は 100 字まで**（lint が）。50〜60 字を超えたら、読みにくくないかを見る（文書 1-6）。
- **文体は、顧客向けなら です・ます、社内メモは だ・である**（content.md の 6）。本文の中で混ぜない（lint が「文体の混在」。引用と箇条書きは数えない）。
- **箇条書きは並列の 3 つ以上に使う。** 理由・条件・因果は段落で書く。1 項目だけの箇条書きは作らない（lint が）。文の箇条書きは全部に「。」、語の箇条書きは全部なし（lint が「句点の混在」）。項目の頭を太字のラベルとコロンにしない（lint が）（文書 1-7、Docs 1-15）。
- **太字は結論の語句だけ。本文 1,000 字に 3 か所まで**（lint が。Docs 1-15。AI の書いた文書は太字が増える）。見出しの中に太字を入れない（lint が）。
- **文をコロンで終えて、箇条書きや表に続けない**（「次のとおりです：」）。文で言い切る（lint が。Docs 1-15）。
- 事実の文は名詞と動詞で書き、主観の修飾語（「大幅に」「非常に」）とぼかし言葉を 1 つずつ吟味する（文書 1-8）。
- 読み手が単独で動けるよう、手順・例外・しなくてよいことも書く。根拠のないところを推測で埋めない（文書 1-9、Docs 1-14）。

## 4. 表と図

- **表は「表 N　題」を表の上、図は「図 N　題」を図の下**（`d.table`・`d.image` の caption。番号は docs.py が通しで振る）。章番号と組み合わせない。題のない表・図は lint が出す（文書 1-10。JIS Z 8301）。
- [visual_doc-001] **表の 1 行目は見出しの行**（濃紺の地に白の太字。テーマ（`[docs.themes]` の `table_head`）で変えられる。ページをまたぐと次のページにも出る）。**表は本文の左端から右端まで広げ、左右の余白は残す**（docs.py が列の幅の比を本文の幅に合わせる）。表の中に表を作らない。セルの中の文は短くし、長い比較は段落で書く。
- **出典は表と図の下の出典の行（`d.src`）にリンクで書く。** 数字のある節（H1・H2）に出典のリンクがなければ、lint が出す（content.md の 6）。
- **図の幅は本文の幅まで**（lint が。余白へのはみ出しは画像で測る）。ロゴ・アイコン・構成図の考え方はスライドと同じ（visual.md の 6）。図の中の文字が読める大きさか、粗くないかはレビューで見る。
- 囲み（引用・コード）は数を絞る（文書 1-10）。

## 5. 画像で測るもの

JSON では、改ページと行の折り返しが分からない。Google が書き出した PDF で測る（`doc_layout.py`。`../doc-build/SKILL.md` の 4）。

- **ページの末尾に残った見出し。** 見出しのスタイルに「次の段落と分離しない」を入れて防いでいるので、出たら書式が外れている。
- **下が 3 割以上空いたページ**（最後のページと、次のページが H1 で始まるページは除く）。次のページに送られた表や図で起きやすい。表を分ける、図を小さくする、順を入れ替える。
- **左右の余白へのはみ出し**（幅を決めた表、大きな図、左の線）。
- **行頭の約物。** Google Docs は前の字ごと次の行に追い出すので、ふつうは出ない（Docs 1-10）。
- **1〜2 字だけの最終行。** 見出し・図表の題・表のセルなど短い段落だけを見る。本文の段落の最終行は直さなくてよい（行が長い文書は改行の頻度が低い。文書 2）。

## 6. スライドの決まりのうち、ドキュメントに当てはめないもの

| スライドの決まり（visual.md・content.md） | ドキュメントでは |
|---|---|
| 1 行 15〜25 字、最終行は 3 字以上、文節で折る、1 つの箱は 8 行まで | 1 行は 40 字まで。本文の段落の改行の位置は直さない。行数の上限はない |
| 文字は 11pt 以上 | 本文 10.5pt。図表の題・出典・表の中・フッターは 9pt でよい |
| 行間 125〜135%（Slides） | Docs の % は行送りの計算が違う。上の 1 の値 |
| 本文の地は Oat Light、表紙は濃紺の地 | 地は白。表紙のページは作らない |
| 見出しは主張の文、見出しだけを順に読む | 章は項目名でよい。段落の 1 文目を順に読む |
| スライドの本文は だ・である か体言止め、です・ます は lint が出す | 顧客向けは です・ます。混在を lint が出す |
| キッカー・結論バンド・淡色の帯、スピーカーノート | なし。要旨の段落で代える |
