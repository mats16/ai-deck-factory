# Commands (slides.py, gslides.py)

Commands for building and checking decks, their options, and the build warnings. Open when you build, or when a build warning appears.

## Commands

```sh
K=<slides-build folder>/scripts   # the folder holding slides-build's SKILL.md. From other skills, that skill's folder + ../slides-build/scripts
C=<deck-practices folder>/scripts   # the parts shared with documents (sheet.py, gapi.py); ../deck-practices/scripts from this skill's folder
cd <folder>/build
python3 $K/slides.py new <Drive folder URL> <YYYYMMDD_name> [--theme <theme>]   # first build. Write the printed URL into the outline and tell the user right away (deck-drive-003 in `../deck-practices/drive.md`)
python3 $K/slides.py lint [pages_<owner>.py | <page>.json] [<URL>] [--pages 3,5 | --all] [--talk]   # after every edit. Turns the build requests into JSON locally without building, and lints them (unit. SKILL.md slides-flow-005. Does not read Google. [themes.md](themes.md))
python3 $K/slides.py lint <workspace>/themes/slides/<name>.json   # checks only the theme file (format, fonts, contrast of role pairs. slides-theme-036 in [themes.md](themes.md))
python3 $K/slides.py plan <URL> [<page>.json …]   # prints what build will write (writes nothing. slides-command-037 below)
python3 $K/slides.py build <URL> [<page>.json …] [--force]   # at checkpoints. Rebuilds, in the same URL, only pages whose content changed (pass files to rebuild only those pages. Stops if the deck was edited on screen. Below)
python3 $K/slides.py dry [pages_<owner>.py | <page>.json] [<URL>]  # runs make without building; prints build warnings and page count (default is deck.json or pages.py. slides-pages-031 in [pages.md](pages.md))
python3 $K/slides.py resolve <page>.json [<URL>]   # prints the resolved form of a JSON page (positions in in, and every value) (slides-pages-034)
python3 $K/slides.py schema [--brief]   # JSON Schema of the JSON page format (--brief is a quick reference of types and keys; read this when writing pages)
python3 $K/slides.py stats    # prints, per key, the number of materials that used writing outside the JSON page format (raw) (slides-pages-035)
python3 $K/slides.py upgrade <file>…   # rewrites raw entries that the format's keys can express (slides-pages-035)
python3 $K/slides.py themes   # theme names, descriptions, whether a template exists, which is the default ([themes.md](themes.md))
python3 $K/slides.py theme <URL> [<name>] [--force]   # writes the theme held by a template or deck to themes/slides/<name>.json ([themes.md](themes.md))
python3 $K/gslides.py check <URL> [--talk]          # after building. lint, text, images of changed pages (/tmp/slides_<first 8 chars of ID>/), box bottom margins measured on images, changed.json (e2e)
python3 $K/gslides.py check <URL> --all             # re-fetches images of all pages (once per checkpoint: before /deck-review, or when looking across pages)
python3 $K/gslides.py check <URL> --pages 3,5       # re-fetches images of those pages only (if the page count changed, all pages automatically)
uv run -q $C/sheet.py /tmp/<name>.png /tmp/slides_<ID>/p-0{2,3,4}.png   # tiles several pages into one image
python3 $K/slides.py merge fix_a.py fix_b.py          # for pages.py materials: merges page functions that child agents wrote in separate files into pages.py (does not build. Below)
```

- The location (Drive folder) and name are in `../deck-practices/drive.md`. Do not create pptx locally.
- Temporary decks for building or trying components separately get `tmp` in their name (`gslides.py check` does not count them in the lint log. Move them to the trash after checking).
- [slides-command-002] **Rebuilding erases edits made in the Google Slides UI, and comments lose their anchors.** Fix the page JSON (pages.py for older materials) and the outline. `build` stops if the deck was edited on screen after the last build (it saves the last ID of the Drive revision list at build time in appProperties and compares; comments, replies, and resolving do not advance it) or if there are unresolved comments. When it stops, put the edits and the responses to comments into the page JSON (pages.py), then rebuild with `--force` ("Working practices" in `../deck-practices/SKILL.md`: fix the page JSON (doc.md for documents) and the outline). Materials built before 2026-10-19 saved the revision in a different form, so the next build stops once. Check Drive `revisions` to confirm there were no edits after the last build time, then use `--force`.
- [slides-command-029] **For pages.py materials, `merge` replaces functions in pages.py with the same-named functions a child agent wrote in `build/fix_<owner>.py`** (functions not in pages.py are added before `make`). Child agents do not write pages.py; they write a separate file, and the parent merges and builds once (`../deck-review/prompt_fix.md` deck-review-011). Only functions are merged; imports come from pages.py (the parent adds names the child used that are not imported). It stops on `make`, constants, or the same function in both files (the parent writes shared code and the page order). The previous pages.py is kept as `pages.py.bak` (if that exists, it is not overwritten: `pages.py.bak1` …). It warns if `make` does not call an added function. Before building, check that the function names in the printed JSON match the owners passed.
- [slides-command-033] **`build` rebuilds only pages whose content changed.** It appends a hash of the page's request content to the end of the page ID, and if the deck has a page with the same hash, it keeps that page and only reorders (the same for added, removed, reordered, or duplicate pages). The hash does not cover the notes: when only the notes changed, it keeps the page and rewrites its notes (so a script written after building rebuilds no page; `../vids-voice/SKILL.md`). Pages built before 2026-10-23 have the notes in the hash: they are kept while their notes stay the same, and a page whose notes changed is rebuilt once. The hash covers the contents of local images, whether the page is the cover (page 1 has its page number removed), and the hashes of linked pages. A page with a link to another page is rebuilt together when the link target is rebuilt (in pages.py decks, also when two or more pages have the same content; JSON pages are told apart by their file names). A deck built by an older `build` rebuilds all pages once, the first time. `--force` rebuilds all pages. Rebuilt pages are written to `/tmp/slides_<first 8 chars of ID>/changed.json`, and `check` fetches only their images. The master's theme is also aligned (slides-theme-036 in [themes.md](themes.md)), so both full and partial rebuilds are decided by the hash of the final requests.
- [slides-command-037] **Look with `plan` before building. You can build selected pages.** Before building, see which pages will be rebuilt or deleted and whether there are on-screen edits or comments, to prevent unexpected rebuilds and erasing on-screen edits. `plan <URL> [<file>…]` prints as JSON what `build` will write (master theme differences `theme`; pages to rebuild or create `rebuild`; pages whose content changed but are kept as before because they were not selected `frozen`; the number of kept pages; the number of pages to delete; the number of reorders; on-screen edits and comments `screen` [if any, `build` stops]) and writes nothing to Google. `build <URL> <file>…` rebuilds only the JSON pages passed (all pages for a deck file) and keeps the previously built slides for the other pages (so that only finished pages are published while other pages are half-written). Previous slides are found by a mark of the page file name put in the page ID. Unselected pages are still created if they link to a page being rebuilt or were never built. The theme belongs to the whole deck, so it is aligned when different even if not passed; passing only the theme file writes only the master. As a theme file, only the deck's own theme file can be passed. `--force` rebuilds only the passed pages (and also skips the on-screen-edit check). For pages kept as before, the links in their previous content in the deck are checked, and they are rebuilt if they point to pages being rebuilt or deleted. The `raw` count (slides-pages-035) is recorded only on full builds. pages.py decks cannot select pages. Pages built by `build` before this change have no mark, so they are rebuilt if their content changed even when not selected (one full build adds the marks).
- When fixing only 1 page of a 53-page deck, `build` went from 23 → 8 s and `check` from 23 → 8 s (median. With the old version, a `check` run that hit 429 waits took 67 s. Rebuilding/fetching all pages still takes 21 s / 20 s. 2026-10-15). `slides.py lint` takes 2–7 s. `build` and `check` print per-step seconds on one line to stderr.
- **Build warnings** are printed to stderr by `lint`, `dry`, and `build`, with the count on the last line (child agents writing pages also check them with `lint` on their own files). They are pre-build estimates, so check the images before deciding to fix or keep. All warnings are listed below (the rule is in the parentheses of each row).
  | Warning | How to fix |
  |---|---|
  | A manually broken line likely does not fit the frame | Rephrase, or move the line break |
  | The last line of auto-wrapped text likely has 2 characters or fewer | Rephrase, or fix the lines with `\v` (slides-visual-013) |
  | The title was shrunk, or the lead likely runs to 2 lines | Shorten the title and the lead (`content.md` §4) |
  | A table cell likely wraps | Rephrase, or change the column widths (`widths`) |
  | The content of a component with `h` likely does not fit that height | Remove `h` (height comes from the content), or shorten the text |
  | The body likely overlaps the conclusion band or the source line | Reduce the content, or split the page (deck-flow-010) |
  | A filled box was made square (`shape: rectangle`) | Remove `shape` unless there is a reason (`visual.md` §4) |
  | A diagram laid out in one horizontal row and joined by arrows | Write it with `"arrows": true` on a `row` (slides-pages-038 in diagrams.md) |
  | An arrow becomes diagonal, a line passes over a component, a label of a diagonal or bent line overlaps a line, arrowheads gather at one point | Change the arrow ends, sides, `route`, or `label_side`, or align the box heights (slides-pages-038 in diagrams.md) |
  | Components partly overlap | Separate them, or put one fully inside the other (slides-pages-038 in diagrams.md) |
  | Text of a Gantt bar is 3 lines or more; a bar chart's name or number wraps | Shorten it, split it with `\n`, or use horizontal bars |
- slides.py runs on plain `python3` (standard library). Only when inserting local images and icons by react-icons name (`Tb…`) does it use global node (pptxgenjs, react-icons, sharp) ([images.md](images.md). Not needed for URL images and Iconify icons).
- [slides-command-003] Plain `python3` has no Pillow, python-pptx, or markitdown, and there is no ImageMagick. Run anything that needs libraries with uv, and put tools in `scripts/` (like `box_pad.py`). Crop images with `sips -c <height> <width> --cropOffset <top> <left> <input> --out <output>` (px).
- Script roles: `slides.py` (components and assembly; page area and color definitions are here too), `template.py` (rebuilding templates), `gslides.py` (checks and reuse), `lint.py` (counting rules), `box_pad.py` (measures on images the space between a box's bottom edge and its text, and the space above and below top-aligned text in light panels; it needs Pillow, so it runs with uv and is called by `gslides.py check`), `gapi.py` (Google API calls: auth, 429 retries, error bodies, uploads). When changing how the API is called, change only `gapi.py`. Per-person values (template URLs and locations, default theme, quota project) are not written in code; they go in `factory.toml` directly under the workspace (the folder above the material folders, e.g. `~/Documents`) (read by `gapi.factory()`. [themes.md](themes.md)).
