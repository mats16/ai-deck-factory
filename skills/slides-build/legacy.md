# Older decks: pages.py and pptx

Open only for decks built with `build/pages.py`, or pptx decks from before 2026-10-07. New decks use the page JSON ([pages.md](pages.md)).

## Writing pages.py (earlier materials, and pages JSON cannot express)

pages.py contains only `NAME` (the material name; append `｜Internal Only` for internal materials and `｜Confidential` for confidential ones), page functions, functions and constants shared across pages, and `make(d)`. The material name is not shown in the footer; only the classification remains at the end of the copyright line. Components are the methods of `Deck` in `slides.py`. [slides-legacy-030] Write one function per page (`p_<content>(d)`), and put only the call order in `make(d)`. When fixes are split among child agents by page, a function is the unit of ownership (`merge`).

```python
from slides import HEAD, NAVY, SUB, RED_TEXT, TEXT, RULE, X, W, INSET   # color roles, and body left edge and width
NAME = "〇〇様_ご説明資料"
def p_cover(d):
    s = d.cover("タイトル", "〇〇様｜2026-10-07", "副題")

def p_summary(d):
    s = d.page("見出し（短い名詞句）", "リード（このページで言えること）", kicker="キッカー（要るページだけ）")
    d.text(s, X, 1.78, W, 1.0, ["本文。", ("強調", {"bold": True}), "。"], spacing=125)
    d.source(s, ["出典: ", ("ブログの名前", {"link": "https://…"})])

def make(d):
    p_cover(d)
    p_summary(d)
```

| Component | What it does |
|---|---|
| `d.cover(title, kicker, sub, variant=1)` | Cover. 2 行のタイトルは、文節の切れ目に `\n` を入れる。 `variant` is the number of the cover pattern in the company template (on the template's sample pages. `../slides-template/SKILL.md` slides-theme-001) |
| `d.divider(num, title, sub, variant=1)` | Section divider. `variant` lets each section use a different divider pattern (background color or artwork) |
| `d.page(title, lead, kicker)` | Body page (kicker, title, lead). Returns the page ID. If the title does not fit on one line, it shrinks it down to 18pt and warns (shortening the title comes first) |
| `d.slide(bg, foot)` | Untyped page. `foot=False` places no footer or page number (pages with a full-bleed image; `reuse.md` Stage 1) |
| `d.text(s, x, y, w, h, parts, size, color, bold, align, valign, spacing, fill, line, bullets, kind, radius, edge, pad, gap, dash, weight)` | Text frame. `parts` is a string or a list of `(string, {"bold", "size", "color", "link"})`. `\n` separates paragraphs, and `\v` is a line break inside a paragraph. Filled frames default to rounded rectangles with radius 0.1 in. `spacing` is line spacing (%). `edge=True` aligns the text's edge to `(x, y)` and width `w` (unfilled text; "Laying out shapes and text"). Left- or right-aligned text with a fill or outline gets one character's width (the smallest text size in the frame; measured the same way as lint) between the box edge and the text (change with `pad`; "Laying out shapes and text"). `gap` is the space between paragraphs (pt). Paragraphs at 2× the base size or larger (large numbers) get 100% line spacing ("Laying out shapes and text") |
| `d.label(s, v, x, y, w, h, fill, color, size, bold, align, radius, pad)` | Tag (a filled box and a short phrase as one shape, such as a date or step name). Default is navy bold text on a PANEL background, centered. When left-aligned, it leaves one character's width between the box edge and the text |
| `d.box(s, x, y, w, h, fill, line, kind, radius, dash, weight)` | Box. Defaults to a rounded rectangle with radius 0.1 in if filled, a rectangle if outline only. `kind="RECTANGLE"` makes a rectangle explicitly. Use either fill or outline (`visual.md` "Laying out shapes and text"). `dash=True` makes the outline dotted; `weight` is the outline weight (pt; if omitted, 2 for red (`RED`) lines (`EMPH_PT`; emphasis enclosures), 0.75 otherwise). An emphasis enclosure is `d.box(…, line=RED, kind="ROUND_RECTANGLE")`; add `dash=True` for dotted (§5, `visual.md` "Laying out shapes and text") |
| `d.code(s, x, y, w, h, lines, hot, size)` | Navy code box. `lines` is one string per line; alphanumerics are monospaced (`MONO`). `hot` lines (0-based) are red bold on navy. Moved from pages.py's `code_box` on 2026-10-09, when a third material needed it |
| `d.card(s, x, y, w, h, head, body=…, items=…, fill, line, step, bullets)` | Card with heading and body ("Laying out shapes and text"). Passing `None` as `h` derives the height from the content (`card_h`). Returns the bottom edge (in). Omitting `head` etc. gives only a box with rules on a `CARD` background (a card whose content you build yourself; pass `h`). `items` flow into one text frame by default (the space between items stays even regardless of their line counts). Items are placed at fixed intervals only when `step` is passed (use it only to align item top edges across left and right cards) |
| `d.num(s, n, cx, cy, size, fill, shape)` | Number. `(cx, cy)` is the center of the shape. `shape` is `"ellipse"` (perfect circle; default) or `"round_rectangle"` (height is the circle's diameter; width is the larger of the diameter and the number's width plus half the diameter; `num_w`). `size` is `"small"` (0.3 in, 11pt; marks inside diagrams), `"medium"` (0.36 in, 14pt; cards and steps; default), or `"large"` (0.48 in, 18pt; large tiers). Sizes are `NUM` in `slides.py` (§4, `visual.md` "Laying out shapes and text"). The digits are `ON_RED` on a `RED` fill and `WHITE` on other fills |
| `d.table(s, x, y, widths, rows, size, row_h, header, first_col, zebra, align, valign, borders)` | Table. Heading rows (`header` is a row count or a boolean) are white bold on navy, the first column is `HEAD` bold, alternate rows are PANEL and the others `CARD`, horizontal rules are RULE (same as the old deck.js; `borders="grid"` for horizontal and vertical, `"none"` for none). `align` is a list per column of `"left"`, `"center"`, `"right"`; `valign` is `"top"`, `"middle"`, `"bottom"`. A cell is a string, a parts list like `d.text`, or a dict (`text`, `colspan`, `rowspan`, `fill`, `color`, `align`, `valign`, `bullets`; do not write positions covered by a merged cell). Returns the estimated bottom edge (in) (rows grow to fit the text while the JSON row height stays at the minimum, so place elements below by this value) |
| `d.arrow(s, x1, y1, x2, y2, color, head, dash, weight)` | Lines and arrows. `dash=True` for dotted (e.g. 「できるが手間」), `weight` for weight (pt; default 1.25) |
| `d.image(s, src, x, y, w, h, alt)` / `d.icon(s, name, x, y, size, color)` | Images and icons ([images.md](images.md)). Put the name in `alt` for logos. Pass SVG URLs as `png(url)` and images in the workspace's `assets/` as `asset("gcp/bigquery.png")` |
| `d.band(s, head, sub)` | Conclusion band. The bottom edge is fixed at 6.60 and it grows upward to fit the content. Returns the top edge |
| `d.source(s, parts)` / `d.note(s, text)` | Source line (adds 「出典: 」 if not at the head) / speaker notes |
| `cols(n, gap, x0, w)` | List of (left edge, width) splitting the width into n columns |

- Pass colors by role name (`NAVY`, `SUB`, `RED_TEXT` etc.; the list is at the top of `slides.py` and in `visual.md` §1). Use `slides.py` names for positions too (`X`, `W`, `Y_BODY`, `BAND_BOTTOM` etc.); do not copy numbers. Role names point to theme colors, so changing the template changes the colors. Colors not in the theme (`TEXT`, `RULE`, `RED_SOFT`, `STAGE_TEXT`, `PUBLIC_PREVIEW`) are also written by name. `TEXT`, `RULE`, `RED_SOFT`, `STAGE_TEXT`, and `DECOR` change value with the theme, and `paint` and icons replace them at build time (the same value written as the default 6-digit hex is also replaced). Roles written by name (`HEAD`, `CARD`, `SUB_ON_NAVY`, `ON_RED`) are not replaced if written as 6-digit hex (because they share their default values with `NAVY`, `WHITE`, and `RULE`). Writing heading text as `NAVY`, or card backgrounds and number digits as `WHITE` or `"FFFFFF"`, makes them unreadable in themes with dark body backgrounds. Get the fill of availability-stage tags with `STAGE_FILL[<GA・Public Preview・Beta・Private Preview・OSS>]`.
- A link to a page (`{"link": 12}`) is attached with that page's ID at build time. Even if pages are added or reordered on screen, it points to the same page.
- If `spacing` (line spacing) of `d.text` is omitted, it is 125 when 2+ lines are expected and 100 for 1 line (`visual.md` §2). Table cells use 120 for 2+ lines.
- The footer (copyright line at bottom left) is added automatically on every page, including the cover and section dividers. The text is `[brand] copyright` in `factory.toml` (the deck theme's `copyright` if present; `COPYRIGHT` in `slides.py`), 9pt (`COPYRIGHT_PT`), `SUB` on body pages, and `SUB_ON_NAVY` on the cover and section dividers (navy background). The material name is not shown; only `Internal Only` or `Confidential` at the end of `NAME` remains. The year of first publication is not auto-updated to the current year. It is not overlaid on reused pages with `foot=False`. Page numbers appear at the bottom right of every page except the cover, in the same 9pt as the copyright line; they are a template frame, so they stay correct when pages are reordered on screen.

Do not copy them from earlier materials.** A component needed in only one material is written as a function in pages.py ("Pages the JSON components cannot express" in slides-pages-034); when a second material needs it, move it into slides.py and the JSON components.

## Laying out shapes and text (pages.py)

In the page JSON, `slides.py` decides coordinates, frames, and padding (slides-pages-034 in [pages.md](pages.md)). This section is for pages.py. Do not align positions by computing coordinates; align with the features of shapes and text frames (`align`, `valign`). This holds up better when text grows, and is easier to fix on screen.

- **Make a shape and the text inside it one object.** Numbers, tags, and words inside arrows are `d.text(…, fill=RED, color=ON_RED, align="CENTER", valign="MIDDLE")`. `finish` groups the rounded background and the text into one editable group. A perfect circle is `kind="ELLIPSE"`. Unfilled text is a transparent rectangle as before.
  - [slides-pages-008] **Build circular numbers with `d.num` and choose the size from small, medium, and large** (circle size and text size have a balance, so do not decide diameter and text size per material. Samples are on the template's component pages). `d.num` uses `d.text(…, kind="ELLIPSE")`. Google places text in a circle a further 0.1 in inside the inscribed rectangle, so in 0.3–0.36 in circles the text area is narrower than a 14pt digit and the digit shifts to the upper right (0.3 in: 3.5 pt right, 2 pt up; 0.36 in: 1.5 pt right. 「10」 wraps to 2 lines). Changing the font does not fix it (with 7 fonts it shifted right by 1.2–2.7 pt). `d.text` makes the circle fill only, overlays a transparent frame the same size as the circle, and groups them (shift within 0.6 pt). In a rectangular frame, even if the text area (the frame minus inner padding) is narrower than the digits, the overflow is spread evenly up/down and left/right and the text is centered. However, 2+ characters wrap if the width is too small (「10」 wraps at a 0.20 in text area and fits on 1 line at 0.22 in). A frame exactly at the estimated digit width wrapped when the font changed character widths slightly (「10」 in a medium circle; #51). So regardless of character count, the width is widened to the larger of the circle and the digit width, plus 0.05 in on each side (no branch that widens only for 2+ characters). The frame is wider than the circle, so do not connect arrows to numbers. Line spacing is 100%. At first the frame was larger than the circle by only the padding (0.1 in), but the frame was too large when selected (the current 1-character frame is 0.1 in wider than the circle). Do not place a circle with `d.box` or `_shape` and put text in it. Rounded-rectangle numbers (`shape="round_rectangle"`) for the same reason overlay, on a rounded background (`d.box`), a transparent frame widened the same way as for circles (`wide` of `d.text`).
- **When a large frame holds several blocks of text, separate frames are fine.** Cards with heading and body are `d.card` (it overlays a slightly smaller text frame on the box. The inner padding of a text frame is 0.1 in and cannot be changed, so the space between frame and text is made here). Use `body` to put the body in one frame, or `items` to list (heading, description) items at even intervals. For complex frames holding numbers, labels, and so on, place the frame with `d.box` and put text frames `PAD` (0.08 in) inside it. [slides-pages-028] Decide the height of `d.card` from its content by passing `None` as `h` (`card_h` estimates the line count, moving alphanumeric words to the next line without splitting them across lines). Do not stretch it to match the neighboring column or the page bottom (in the records of the three representative pages, boxes larger than their content appeared in almost every deck). To align column heights, pass the maximum `card_h(w, head, body=…)` of the cards in the row. For cards mixing text of different sizes (large numbers) and for `d.box`, the caller decides the height. The inner text frame is not clipped when it overflows the box and is drawn as is, so when you add items or lines, also fix the box height (`step` in `items` uses the same interval for every item, so it overflows easily when an item with many lines comes last). Check the space between the last line and the bottom edge with 「要確認（画像で測った）」 of `gslides.py check` (`visual.md` §4. 2026-10-09).
- **Align `y`, `h`, and `valign` for text placed side by side.** Cards placed side by side, numbers and headings, labels and body text, and so on get the same frame top edge and height, and the same `valign`. Things placed one line each (numbers and headings etc.) are centered with `MIDDLE`. Cards with different amounts of text use `TOP` so the heading heights match.
- **Put text stacked vertically in one text frame, separated by line breaks.** For things stacked top and bottom, such as heading and body or label and supplement, list `("見出し\n", {"bold": True})` and the body in `parts`. Do not make separate frames with shifted `y`.
- **Make the source line runs with a link per name.** Like `("Mandiant M-Trends 2026", {"link": url})`, attach links to the names of blogs, talks, and docs, and keep connecting 「、」 and parentheses as plain strings. Link to the Appendix source page with `{"link": <page number>}`. Use the same URLs in the source line and in the Appendix list (in pages.py, put them in one place at the top). In JSON, write `[name](URL)` and `[name](#p12)`. lint reports source lines without links as `要確認` (2026-10-06).
- [slides-pages-011] **To align a text's left edge with the edge of another element, use `d.text(…, edge=True)`** (moves the frame outward by `INSET` (0.1 in); `page`, `source`, and `cover` already do this). Do not put a function in pages.py that moves frames outward (the old `t()`) (so that each material does not carry the same function).
- [slides-pages-012] **For text left- or right-aligned in a filled box, passing the fill to `d.text` or `d.label` makes the space between the box edge and the text one character wide** (`visual.md` §4). The inner padding of a text frame is 0.1 in and cannot be changed, and even at 11pt it is less than one character, so the text frame is shrunk inward and grouped with the shape. When overlaying text on a `d.box`, keep the text edge at least one character away from the box edge. lint reports as `要確認` text whose space from the filled box's edge is narrower than one character (the smallest text size in that frame).
- [slides-pages-013] **When putting a large number and its description in one frame, do not adjust line spacing to match the number.** `d.text` sets 100% line spacing only for paragraphs at 2× the base (`size`) or larger (with 125% left as is, Google's line advance is wider than pptx, and the number and description looked apart).
- Build gridded diagrams (Gantt, comparison tables, matrices) as a table, not from rectangles and lines (slides-pages-009 in [diagrams.md](diagrams.md)). `vlines` of `d.table` (`(first column, number of columns)`) draws vertical rules in those columns below the heading row (`gantt` uses it for month boundaries). Rule shading (light between months, dark at item boundaries) is not supported. When needed, add a component (set `tableRange` of `updateTableBorderProperties` to the cell range).

## pptx decks from before 2026-10-07

- They were made with pptxgenjs or python-pptx, and the pptx was uploaded to Drive. build.js files that load `deck.js` (8 of them) do not work unless changed to load `deck.js` from the workspace's `Archive/pptx_pipeline_20261007/skills/office-jp/scripts/`. build.js files that carry copied components work as is. When fixing one, ask the user whether to fix it as pptx or rebuild it in Google Slides (the steps for fixing as pptx are in that Archive's `README.md`).
- Decks from before 2026-10-06 were made before the 11pt text minimum and the current colors (visual.md). When rebuilding, ask the user whether to bring the whole deck in line with the current rules.
- [slides-legacy-026] **When rebuilding in Google Slides**: rewrite build.js pages as page JSON (slides-pages-034), without changing the content (headings, body, notes). Use JSON components, and do not copy deck.js components (only what JSON components cannot express becomes pages.py functions). Coordinates can mostly be reused, but these 6 things broke.
  - Unfilled text that had `margin: 0` in pptxgenjs shifts by Google's frame inner padding ([api.md](api.md)). Use `d.text(…, edge=True)` ("Laying out shapes and text"). Use `d.label` for filled tags and `d.num` for numbers
  - `row_h` of `d.table` also applies to heading rows. For rows that should grow with content, make `row_h` small and let rows grow to fit the text
  - Left-aligned filled tags that took left padding with pptxgenjs `margin` (12pt etc.) fell short of one character in Google, because inner padding is fixed at 0.1 in. Passing the fill to `d.label` or `d.text` leaves one character's space ("Laying out shapes and text")
  - Putting a large number and its description in one frame at 125% line spacing made them look apart, because Google's line advance is wider than pptx. `d.text` sets 100% line spacing only for the number's paragraph ("Laying out shapes and text")
  - Grids built from lines (Gantt) are converted to tables, and boxes for people or products that were text only get icons and logos (§4, `visual.md` §6). The added items narrow the text width, producing last lines of 1–2 characters, so check on images and tighten the wording
  - The URL changes (it cannot be built into the pptx URL). Keep the previous pptx on Drive, and ask the user whether to delete it. List both in references_index.md, and write which is the current version
  - [slides-legacy-027] Do not copy build.js components (text, box, chip, table etc.) as a component set with the same calls. If building with pages.py, put in only the small functions that material needs (text edge alignment is `edge=True`, tags `d.label`, numbers `d.num`, white cards `d.card`; do not copy these into pages.py). Confirm the approach with the user, and if over 10 pages, check the three representative pages (step 6 in [workflow.md](workflow.md)) yourself before building the whole deck.
