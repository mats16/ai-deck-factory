# Templates and themes

Open when you choose, copy, or change a theme, or create a deck from a template. Making a template from a company template is `../slides-template/SKILL.md`.

## Templates and themes

`template.py <theme> --from-base` creates templates in the "Themes" folder under `[drive] factory` (the root of personal materials) (it creates the folder if missing; it does not keep the folder's ID or URL). The templates in use are written one per line in `[slides.templates]` of the workspace's `factory.toml` as "theme name = URL" (`template.py` writes them). The URL of the base template is not kept; pass it when creating with `template.py <theme> --from-base <base URL>` (the one given in the conversation. If not passed, it is created from a blank pptx `assets/blank.pptx` converted and uploaded to Google Slides [contents in `assets/README.md`]). The scripts read from here (this owner's visual and company are in the "Templates" folder made earlier). They are copies of Databricks's 2026 internal template with the following changes (`template.py`).

- Kept only the master "Databricks Theme" and the layout "Content E - Blank" (deleted 98 sample pages, 38 other layouts, and the master "Simple Light").
- Deleted the master's copyright line (©2021) and logo, and Blank's full-page rectangle (it covers the page background). slides.py writes the footer.
- Made the master's color scheme (12 colors) the theme colors. Set the placeholder font to Noto Sans JP.
- Set the page-number frame to the same 9pt as the copyright line (`COPYRIGHT_PT`), line spacing 100, and the secondary color (SUB), with its right edge at the body's right edge (12.73 in) and its top edge at the copyright text (7.18 in) (this frame has 0 inner padding). Since size and top edge are the same, text heights on the left and right match.
- Built the sample pages (cover, section divider, color quick reference, and two component pages) with slides.py. The component samples follow the rules (visual.md); after changing components, check here for breakage (2026-10-08, `Research/slides_template_review_20261008.md`). When copied by `new`, the sample pages are removed and replaced by the pages of deck.json (pages.py).

There are two built-in themes (`themes/visual.json`, `themes/company.json`). The mapping of roles to colors is `visual.md` §1. Themes made from other companies' templates (the company's fonts and colors) are in `../slides-template/SKILL.md`.

- [slides-theme-036] **Write a theme in a theme file (`kind: theme`).** The workspace's `themes/slides/<name>.json` (the file name is the theme name; alphanumerics and - _). It takes priority over a built-in theme of the same name. It uses the same `apiVersion` as page JSON (slides-pages-035), and its format is in `slides.py schema`. Document themes will later go in `themes/docs/<name>.json` in the same format.
  ```json
  {"apiVersion": "slides/v1", "kind": "theme",
   "description": "アクメの会社の色のテーマ。顧客に出す提案・説明と社外の登壇に使う。社内の勉強会には使わない（visual）",
   "font": "Noto Sans JP", "mono": "Cascadia Mono", "copyright": "© 2026 Acme, Inc. All rights reserved.",
   "colors": {"NAVY": "002B5C", "RED": "E4002B", "TEXT": "303F47", "HEAD": "002B5C"},
   "cover": ["Title Slide 1", "Title Slide 2"], "section": ["Section Break 1"]}
  ```
  `colors` maps role names (`visual.md` §1), colors not in the theme (`TEXT`, `RULE`, `RED_SOFT`, `STAGE_TEXT`, `DECOR`), and roles written by name (`HEAD`, `CARD`, `SUB_ON_NAVY`, `ON_RED`) → 6-digit hex without `#`. Roles not written use the visual colors, and values not written use the defaults (font Noto Sans JP, monospace Cascadia Mono, `copyright` from `[brand]`). `cover` and `section` are the names of cover and section-divider layouts kept from the company template; `template.py` measures and writes in the text width (`w`) and background brightness (`tone`) (`../slides-template/SKILL.md` slides-theme-001). Sample: `samples/json/theme.json`.
- **Check only the theme file, without reading Google.** `python3 $K/slides.py lint themes/slides/<name>.json` checks the format, fonts, and contrast of role pairs (for pairs that fall short, it suggests a fix that keeps hue and saturation and changes only brightness). Page `lint` and `dry` also take the theme's colors, fonts, and cover and section-divider patterns from the theme file, so they do not read Google (even if a URL is passed, they do not read it if the file for `deck.json`'s `theme` exists. The URL is needed only for decks without a theme file. Local layout backgrounds use the representative color of `tone` [NAVY for dark, RED for accent, BG for light]; photo and shape backgrounds are not checked).
- **The deck holds every value of the theme.** `template.py` writes `ai-deck-factory theme=<name>` into the alt text of the page-number frame on the template's master, together with a JSON of the values that do not fit in the master's color scheme, fonts, and cover/section-divider markers (`description`, `mono`, `copyright`, colors not in the theme, and roles written by name); it stays in copied decks.
- **Every build aligns the deck's master to the theme file.** `slides.py build` (and `new`), after checking for on-screen edits, rewrites the deck master's color scheme, fonts, and markers if they differ from the theme file (it prints what it wrote to stderr). Role colors point to master colors, so if only color values changed, only pages that baked in values, like icon colors, are rebuilt (content hash; slides-component-016). Changing the font changes the text and character-width estimates on every page, so all pages are rebuilt. After the master is written, the next `gslides.py check` does not use earlier images and re-fetches all pages (colors change even on pages whose IDs did not change). It stops when the cover and section-divider patterns (the list of layout names) differ, or when `tone` has not been measured (shapes and logos exist only in the template's layouts; re-align with `template.py` and recreate with `new`). Decks of themes without a theme file (other people's themes) are built with the values the deck holds.
- **Write back from slides to a theme file.** `python3 $K/slides.py theme <template or deck URL> [<name>]` writes `themes/slides/<name>.json` from the master's color scheme, fonts, and markers (if the name is omitted, the name in the deck's marker). Colors and fonts changed in the on-screen theme builder are included. For a template (one with the theme name in its Drive properties), it also writes the URL to `[slides.templates]` (a template can be copied only under the same name as its marker). If a file of the same name exists with different values, it stops (`--force` replaces it).

**Choose the theme per material** (step 5 in `../deck-practices/start.md`). The way to find themes is modeled on Agent Skills: choose by description from the list of names and `description`s printed by `slides.py themes`.
- [slides-theme-032] **Company-wide shared themes.** Shared themes are used just like your own: with a theme file and a URL in `[slides.templates]` (shared and own are not distinguished). `template.py` writes `description` into the Drive description of the template it made, and the theme name (`adf.theme`) into the Drive properties (public; readable by any OAuth client). The values used at build time are in the master's markers. `[drive] shared_themes` (the company-wide shared theme folder) is read only when searching; `slides.py themes` lists templates that `[slides.templates]` does not point to as 「共有。」 with their URLs. Names in Themes under `[drive] factory` (your own) that are not in `[slides.templates]` are also listed, the newest one, as 「個人。」 (to find ones made in other workspaces. Older ones before a recreation are not listed, because the same name exists). To use one, run `slides.py theme <printed URL>` (it copies the theme file and writes it to `[slides.templates]`; if the same name exists, it replaces the current template). An administrator may make the Themes folder under their own `[drive] factory` the shared theme folder. Give users view permission only.
- **When two or more themes have templates and `new` is run without `--theme`, it prints the list and stops** (to prevent forgetting to choose. It does not stop for temporary materials in kaizen's verification).
- **`description` is the only clue for choosing.** The agent chooses by looking only at `slides.py themes` (list of name, whether default, whether a template exists, and `description`). In 1–3 sentences, write what the theme is, which materials and audiences it is for, and when not to use it (and which to use instead). Including words for material types and audiences (「顧客向けの提案」「社内の勉強会」) makes it easier to choose. Descriptions of built-in themes are in the built-in files (to change one, copy a file of the same name into the workspace and edit it).

- **The template decides only the theme colors, page size (13.33 × 7.5 in), page-number position, and the cover and section-divider shapes kept from the company template (`../slides-template/SKILL.md` slides-theme-001).** Text sizes and placement are written per text by the pages (deck.json or pages.py), and the page number's size and line spacing are written by slides.py at every build (values written per text take priority over the template).
- **Pages of a created deck are a copy of the template at the time it was copied.** Theme colors and fonts are aligned to the theme file at every rebuild ("Every build" above), but the shapes of the template's layouts do not change. To switch a deck to a different theme, recreate it with `new` (the URL changes).
- To change colors, edit the theme file (built-ins are `themes/<name>.json`), measure with `slides.py lint <file>`, then run `template.py <theme>` (re-aligns the template's color scheme, fonts, and samples; the ID does not change). Created decks align when rebuilt. Check the contrast of the rendered colors with `gslides.py check <template URL>`.
- When the company template is updated, recreate with `template.py <theme> --from-base <new URL>`. `template.py` writes the URL of the created template into `[slides.templates]` of `factory.toml` (do not copy it by hand). Delete the previous template or add 「旧」 to its name. If it is in the shared theme folder, remove it from the folder (renaming keeps the Drive properties, so two themes of the same name appear; this shows up in factory-doctor's 「共有テーマ」).
- [slides-theme-007] **`factory.toml`** (directly under the workspace; factory-init places it and factory-doctor checks it): holds only per-person values (template URLs [`[slides.templates]`] and locations, default theme, quota project, root of the Drive locations; theme values are in theme files). Do not put visual rules (colors, padding, page area) there. Scripts look for it in the current folder, then walk up from the script's folder, and stop if not found. When someone else uses the scripts, they copy `factory.toml`, set their own values, and create their own templates with `template.py visual --from-base` and `template.py company --from-base` (how to write it is in the comment at the top of `factory.toml`).
- Templates are not shared with anyone. Even when sharing, do not share automatically, and do not use `anyone`.
