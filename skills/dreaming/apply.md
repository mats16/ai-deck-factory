# Applying proposals (when the user replies 「適用」)

This can be the thread that ran the cleanup or a different conversation. When you write a new proposal here (after an apply stops, or when an answer changes a rule), "Rules for running" in [run.md](run.md) still holds: no confidential information in rules, do not repeat rejected proposals, and do not overturn what the user decided.

`R` is the workspace (the folder with `factory.toml`, e.g. `~/Documents`), `D` is this skill's folder (where the plugin is installed), `S` is the record folder `$R/.factory/dreaming`, and `K` is `$D/../slides-build/scripts`. Run `cd $R` first (every script in `scripts/` reads the current folder as the workspace). Relative paths written in AGENTS.md and skills (`Customers/…`, `Internal/…`) are relative to `$R`. `L` is `$D/../deck-practices/scripts/ledger.py`. The report is the newest `$S/log/<YYYYMMDD>.md` ("Report format" in [run.md](run.md)).

1. Decide which proposals. For 「推奨どおり」, take the P-IDs in the newest report that still appear in `python3 $L pending` and split them by recommendation. Apply 「適用」 ones in step 2, reject 「却下」 ones with `python3 $L reject <P-ID> --reason '推奨どおり（<推奨の理由>）'`, and leave 「様子見」 ones as they are. `answer` pending questions with the recommended answer. Only for the ones the user called out (「P0002 は却下」 etc.), do as told. When the user chose one by one through questions, do as chosen. For just 「適用」, take all P-IDs in the newest report that appear in `python3 $L pending`, the findings marked 「戻さない」 in the report, and all M-numbered proposals. Do not include pending questions (wait for answers).
2. `python3 $L apply <P-ID …>`. It applies only when the current text exists exactly once, and sets the source findings' destination to the rule ID. If it stops (the target changed after the proposal), show the adjusted text and ask, then `propose` anew and apply it.
3. For ones the user rejected, `python3 $L reject <P-ID> --reason <reason>`. For findings marked 「戻さない」 in the report, `python3 $L route <c-ID> 戻さない`. Proposals to the plugin (shown as 「プラグインの skills/…」 in `pending`) are not applied by `apply`. File an Issue with the `factory-kaizen` skill, and after filing run `python3 $L sent <P-ID> --issue <URL>` (the source findings get linked to that rule). If the Issue is closed without being merged, `python3 $L reject <P-ID> --reason <reason>` (the findings return to their previous destination). Record answers to pending questions with `python3 $L answer <Q-ID> --a <the user's words (verbatim)>`. If the answer settles a rule, also add `python3 $L add --deck <material folder> --quote <the answer verbatim> --decided --to <destination>`, and if a rule needs to change, make it a proposal. For M-numbered proposals, edit by hand after `sh $D/scripts/snapshot.sh save` (it includes memory).
4. Run the checks in step 6 of [run.md](run.md), and check that AGENTS.md is 20,000 bytes or less (4h in run.md).
5. Reply with the changed files and how to undo (`python3 $L undo <P-ID>`).
