# Videos from slides (Google Vids, beta)

**Beta.** Vids has no public API for editing. This skill writes a video through the same internal calls the Vids editor makes, from a tab of a Chrome that is signed in to the target Google account. The empty Vids, the MP4, and the record on the file go through the public Drive API, and the notes through the Slides API (`../deck-build/scripts/gapi.py`, the same authentication as building slides). The internal calls are listed in [internal_api.md](internal_api.md). They can change without notice, so this skill is a stopgap: when Google publishes an editing API, a skill on that API replaces this one. When a step fails with an error from 「Vids の内部 API」, see "When it fails".

Make the video from the deck itself, and do not copy the Slides into a separate deck for the video, because two decks with the same pages drift apart at every fix and `update` follows only the deck recorded on the Vids. The script of each scene is the page's speaker notes as they are, and every deck's notes are written as that script (`../slides-speaker-notes/SKILL.md`).

## Setup

- **A Chrome DevTools (MCP) that can reach the target Google account.** `vids.py` connects to that Chrome's remote debugging port, opens a background tab on `docs.google.com/videos`, runs `scripts/vids_client.js` there, and closes the tab. The Cookie and tokens stay inside that tab; the script returns only IDs, counts, and lengths. Use the Chrome that the Chrome DevTools MCP of this conversation drives, if it is signed in to the account that owns the deck. If it is not running, start it the way that MCP's setup says.
- The address is `--browser <URL>`, else the environment variable `VIDS_BROWSER`, else `browser` under `[vids]` in factory.toml, else `http://127.0.0.1:9222`.
- Run with `uv run` (it installs `websockets` and Pillow). `--selftest` also needs `node`.
- The public OAuth token (gcloud ADC) does not work for Vids' editing calls (403, checked 2026-10-21), which is why a signed-in Chrome is needed.

## Steps

Run anywhere under the workspace (factory.toml is found from the current folder upward).

```sh
V=<vids-beta folder>/scripts/vids.py
uv run $V create <Slides URL> [--voice Elio | --avatar Oliver --layout build/vids_avatar/avatar_layout.json] [--name 名前] [--no-music]
uv run $V layout <Slides URL> --pages 1,5|all [--out build/vids_avatar] [--reset]
uv run $V update <Vids URL or the Slides URL> [--voice 名前 | --avatar 名前|none] [--layout …/avatar_layout.json] [--rebuild [--no-music]]
uv run $V check <Vids URL> [<Slides URL>]
uv run $V voices
uv run $V avatars
uv run $V download <Vids URL> <out.mp4>
```

1. **Voice only or AI avatar.** Unless the request says which, ask the user before `create`: voice only (which voice, default Elio), or an AI avatar that reads the notes on screen (which avatar; its voice comes with it), and on which pages. Show the choices from `voices` and `avatars`. Suggest a few pages (for example the cover and the summary) rather than every page, because each avatar scene uses one of the month's avatar generations ("AI avatars"); the other pages are read by voice only, in the avatar's voice.

2. **Check the notes.** Run `lint` of slides-speaker-notes on the deck's notes. If they are not a script yet (a deck built before the default, or notes holding sources and supplements for readers), rewrite them in the same deck by the steps of slides-speaker-notes, and move what readers need from the notes to the source line, the body, or the Appendix of that deck (in the page JSON, then build and lint by `../deck-build/SKILL.md`). Ask the user before moving anything to the pages. `vids.py` stops if a page's notes are longer than 2,500 characters (Vids' limit per scene). A page with empty notes becomes a scene without voice.
3. **Place the avatar (avatar only).** Run `layout --pages <the chosen pages>` (`all` for every page; the other pages get `none`). It finds, on Google's image of each of those pages, the largest empty corner for a circle (bottom right preferred; on the cover, page 1, it tries larger circles first, up to 0.6 of the page height) and writes `avatar_layout.json` and `avatar_sheet-<n>.png` (the pages with the circle drawn in red, 16 per sheet). Look at every sheet. Fix a page in the JSON when the circle covers or touches text, a figure, a photo, a logo, or a panel, or when it hides what the scene talks about: change `corner` (`br`, `bl`, `tr`, `tl`) or `size` (the diameter as a fraction of the page height, 0.05 to 0.9; make the cover larger or smaller here when the user asks), or set `corner` to `none` for a page that should be read by voice only (for example a full-page figure). Pages with `"check": true` had no empty corner and got the smallest circle at the bottom right; decide each of them. Run `layout` again without `--pages` (it keeps the JSON and redraws) and look again until no page needs a fix. To change which pages have an avatar, run it with `--pages` again: pages already placed keep their place. The check is on the slides' images because the scenes are the same pages; Vids does not need to be open. Adjustments that need the scene itself are made after `create`, on screen ("Adjusting avatars in the editor").
4. **Close the Vids in every browser tab** before `create` (on `--rebuild`), `update`, and `check`, because saving fails with HTTP 550 while the same Vids is open in an editor tab. `vids.py` stops if it sees such a tab in the Chrome it connects to; tabs in other browsers it cannot see.
5. **`create`.** It makes the Vids in the folder of the Slides, with the name `<Slides の名前>_動画` unless `--name` is given. It turns every page into a scene, puts each page's notes as the scene's script, makes the voiceover of every scene with the chosen voice (with `--avatar`, the avatar video of every scene placed by `--layout`, and a voiceover in the avatar's voice on `none` pages), adds the background music that Vids picks (`--no-music` to leave it out), and deletes the empty scene that a new Vids starts with. Then it reads the Vids back and stops with 「要修正」 unless the scene count, every scene's script, and every voiceover or avatar match the notes and every scene is read by the chosen voice or avatar (`check` does the same with the recorded ones). It records the Slides ID, the voice, and the avatar on the Vids file (Drive `appProperties`: `vidsSlides`, `vidsVoice`, `vidsAvatar`), so `update` needs only the Vids URL. A 4-page deck took about 90 seconds, and a 38-page deck about 10 minutes (22 minutes of voiceover); an avatar takes about a minute per scene, three at a time. Keep the command in the foreground or in a background job that waits that long.
6. **`update` after the notes change** (for example after `speaker_notes.py push`). Pass the Vids URL, or the Slides URL to find the Vids made from it by `create` (it stops if there are none or several). It compares each scene's script and voiceover or avatar with the current notes and the recorded voice and avatar (the voice is read from the label of each voiceover, such as 「… - Elio」, and the avatar from the ID of its element), and replaces the script and the voiceover or avatar of the scenes that differ, keeping the other scenes, the music, and edits on screen to the scenes. An avatar keeps its place, also one moved on screen; with `--layout`, avatars whose place differs from the JSON are moved without making them again. `--voice` or `--avatar` (`none` for voice only) records the new choice first and then replaces every scene, so if a voice change stops partway, `update` without it finishes the rest. If adding or changing avatars stops partway, run the same command again with the same `--layout`: scenes already done are kept, and only the rest are made (without `--layout`, scenes still on voice would stay voice only). Switching from voice only to an avatar needs `--layout`, and so does a scene of an avatar video that had no notes and now has some (it has no place yet). In an avatar video, `--voice` alone keeps the avatars and stops unless the voice is the avatar's; avatars are removed only by `--avatar none`. It stops if the number of pages differs from the number of scenes.
7. **`update --rebuild` after pages change** (layout, text on the page, pages added, removed, or reordered). It builds all scenes again from the slides in the same Vids (same URL and sharing), then deletes the old scenes with their voiceovers, avatars, and music. With an avatar, run `layout --reset` and step 3 first and pass `--layout`, because the pages changed. If it stops after the old scenes were deleted, run the same command again (a plain `update` cannot place the missing avatars). Edits made on screen in Vids are lost; say so before running it.
8. **Deliver.** Give the Vids URL, the scene count, the voice or avatar, and the total length of the voiceovers that `create` prints. With an avatar, also give how many avatar generations are left this month (printed as 「avatar の今月の残り」). Give an MP4 only when asked (`download`; it waits for Vids to render, up to 10 minutes).

## Voices

`voices` lists the 30 Conversational voices (the display name in Vids, the name of the Gemini voice, and the description on screen). `--voice` takes either name. The default is Elio, the default of the Vids editor. Only Elio and Nyla have been used to make a whole video (2026-10-21); if another voice fails, tell the user which one.

- The Classic voices (Narrator, Educator, and so on) are not supported. They are the only voices offered when making a video from slides on screen, and they read audio tags aloud (`../slides-speaker-notes/SKILL.md`, slides-speaker-notes-004).
- The voice shown in Vids' voiceover panel is the user's last choice, not a setting of the video. If the user later presses 「Update voiceover」 on screen, Vids uses the voice in the panel, so tell them to choose the same voice there first.

## AI avatars

`avatars` lists the 30 avatars that speak with a Conversational voice (name, ID, style on screen, and voice). `--avatar` takes the name, the ID, or a voice (the avatar that speaks with it: `--avatar Elio` is Oliver). Each of the 30 voices has exactly one avatar, and the pages without an avatar are read in the avatar's voice, so the voice stays the same across scenes. With both `--voice` and `--avatar`, `vids.py` stops unless the avatar speaks with that voice and names the one that does. To add avatars to a video made with voice only, pass its voice (`update --avatar Elio --layout …`). Only Oliver has been used to make a video (2026-10-22); if another avatar fails, tell the user which one.

- The Classic avatars (Olivia, James, and so on) are not supported. They are the only ones offered when making a video from slides on screen, and they cannot use a Conversational voice. `vids.py` passes the avatar ID directly, after building the scenes, which is how the other avatars can be used.
- Each scene's avatar is its own generated video: the scene's notes are read by the avatar's voice, and the face moves with it. Avatar generations are limited per user and month by the Workspace edition (Business Starter 10, Standard and Plus 25 in Google's help; 50 on the account tested, 2026-10-22), and reset on the 1st; voiceovers are not counted on business and education editions. More needs a higher edition or the AI Expanded Access add-on, which the user's admin decides. A new video uses one per scene with an avatar, `update` one per scene whose notes changed, and moving uses none. `vids.py` makes one avatar first, and if the rest do not fit, places that one and stops.
- The avatar sits in a circle cut from the center of its 16:9 video, on top of the page. Realistic avatars bring their room as background. Avoid avatars on pages where nothing can be hidden (`none` in the JSON).

### Adjusting avatars in the editor (Chrome DevTools)

`vids.py` makes, replaces, deletes, and places avatars; use it for those, because it counts generations and saves the same way every time. Its placement only picks a corner and a size from the slides' images. Fine adjustments are better done on screen in the Vids editor through the Chrome DevTools (MCP), where the scene is seen as it plays: the face off center in the circle, a crop or a size that needs a nudge, a border or shadow, or an overlap that shows only in Vids.

- Do it after `create` or `update` has finished. Open the Vids in a tab of the Chrome that `vids.py` uses, look at each avatar scene (a screenshot of the canvas), and fix only what is wrong: drag the avatar or its corner handles, use 「Crop video」 and 「Mask video」 in the toolbar, or 「Format options」 (size, position, drop shadow). Take a screenshot again after each fix.
- Close the tab when done, before any `vids.py` command, because saves fail while the editor is open.
- `vids.py` keeps those edits: `update` replaces an avatar in its current place and keeps its shape, crop, border, and shadow, changing only the video. `update --layout` moves avatars back to the JSON, so after editing on screen, do not pass `--layout` unless the JSON is meant to win (update the JSON or leave it out). `--rebuild` loses all edits on screen.
- If an editor control or its behavior differs from this description, describe what you see to the user instead of guessing.

## When it fails

- **HTTP 550 on `save`.** The save was refused and nothing was written. It happens after many saves in a short time (to the same Vids, for example `update` right after `--rebuild`, and also to other Vids of the same account), and then lasts several minutes. The client waits and resends up to three times (a few minutes in all). If it still fails, check that no tab has the Vids open, wait about 10 minutes, and run the same command again: a failed `create` moves its Vids to the trash, and `update` starts from what is saved. When `create` or `update` had to wait, it prints 「保存が 550 で断られ、待って送り直した」.
- **`Chrome につながらない` / `Vids を開けない`.** The Chrome is not running with remote debugging, or is not signed in to the target account.
- **`avatar の残りが今月 …`.** The month's avatar generations are not enough for the deck. Tell the user the count, and offer voice only, fewer avatar pages (`none`), or waiting for next month. The one avatar made is placed before stopping (with `create`, it goes to the trash with the Vids).
- **`下書きの応答にシーンのコマンドがない`, `音声の応答に一時ファイルがない`, `avatar の応答に生成の ID がない`, `avatar の生成が動画なしで終わった`, or an error from `genai`.** Vids changed its internal calls, or the account cannot use Gemini in Vids. Do not guess new formats from the error; report it to the user with the message, and record what changed in [internal_api.md](internal_api.md) after checking it in the editor.
- **`--rebuild` stopped partway.** The new scenes may have been saved while some old scenes are still there, so `update` stops on the scene count. Run `update --rebuild` again: it treats every scene there as old and deletes them after building.
- After any failure, run `check` before telling the user the video is ready.
