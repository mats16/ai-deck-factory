# 10 レイアウトで分かることを、補助のラベルで言い直さない

左右の流れの比較・大きな数字・並べた段・手順のページで、見出しやレイアウトで分かることを言い直すだけの補助のラベルと説明（大きな数字の下の `sub`、結論バンドの `sub`、見出しを言い直すキッカー、流れの段ごとの説明の行）を足さずに書けるかを見る。2026-10-23 に slides-visual-047 を足したとき、直す前と後で 2 回ずつ書かせて比べた依頼を残したもの（README の「決めたこと」）。

## 依頼文

```text
slides-build のスキルを使い、社内向けの資料「問い合わせ対応の自動化｜Internal Only」を JSON のページで 5 枚書いてください。
表紙、いまの対応の流れ（受け付け → 担当者が読む → 担当者が調べる → 回答）と、自動化したあとの流れ（受け付け → 分類 → 回答の下書き → 担当者が確かめて回答）を左右に並べたページ、
一次回答までの時間が 45 分から 3 分に縮んだことを大きな数字で見せるページ、自動化の 3 つの段（分類・下書き・確かめ）をそれぞれの役目と並べたページ、来月から始める 3 つの手順のページ。
数字の出典はすべて「社内の試算（2026 年 9 月）」とする。
Internal/fixture_10/build/ に deck.json と 1 ページ 1 ファイルの JSON を書き、slides.py lint deck.json を回して要修正を 0 にしてください。組まないでください。
```

## 見るところ

- 要修正が 0 で、`raw` を使っていない。
- 大きな数字のページで、2 つの `stat` に同じ `sub`（「受け付けから一次回答まで」など）を付けていない。何の時間かは見出しかリードで 1 度だけ言う。
- 大きな数字のページに、キッカー「数字で見る」を置いていない（数字のページなのはレイアウトで分かる）。
- 手順のページの見出しが「3 つの手順」なら、キッカーに「次の手順」を置いていない。結論バンドを置くなら、`sub` は本文にないこと（決めてほしいこと・期限）だけにしている。
- 流れの比較のページで、段の名前を言い直すだけの説明の行（「回答」の下の「回答を書いて送る」など）を段ごとに付けていない。
